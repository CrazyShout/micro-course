# 先把一讲教顺：微课的教学组织与写作标准

更新：2026-09-18。来自用户对两篇文章样板的实际反馈：开头不能在尚未介绍任务、对象和方法时就问“模型为什么偏向某类”。文章版式、公式正确、栏目齐全，都不能替代清楚的讲述顺序。

## 一、先读老师的材料，再设计学习路径

对每个 Lecture（CS5489）或 Chapter（CS5222），先核对原目录、引入例子、关键推理、课堂代码、总结和配套任务。区分原文明确的目标与我们根据顺序推断的主线；不声称知道老师未写出的意图。

围绕三个问题设计：学生要学会什么、讲解怎样帮助他学会、什么任务能检查是否学会。目标、讲解、练习应对齐。依据：[CMU 教学设计原则](https://www.cmu.edu/teaching/assessment/basics/alignment.html)。具体例子要连接抽象表达，图和文字共同解释，示范与独立练习配合；参考 [IES 教学指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)。这些依据提供设计原则，不证明某个模板对所有课程都最优。

## 二、三层组织

课程 → 老师的 Lecture/Chapter → 本讲导读、概念微课、配套 Tutorial、关联 Assignment、本讲回顾。

- 导读交代与前一讲的关系、中心问题、路径及学完应能做的事；不堆概念清单。
- 微课按概念依赖展开。不要为了“一项术语一页”或固定时长强行拆散问题。
- Tutorial 按真实题号、Notebook 任务组织；一个自编算例不能代表整份 Tutorial。
- Assignment 讲问题拆分、方法选择、验证与复现。跨章作业维护一份内容，在相关讲次提供入口。
- 当前缺失的任务文件明确未下载；历史材料留在 Extra Resources。网络课用 Chapter，不捏造 Lecture 编号。
- Research Report 属课程级跨章实践；技术指导放学习活动，评分/截止/提交手续仍放信息栏。

网页的教学分组是新增的引用关系，不改变 Markji 卡片章节、ID、root ID、学习记录和原深链。

## 三、概念微课怎样开头和推进

1. **交代事情**：谁遇到什么问题，已有何种记录/测量，希望知道什么。第一段不能依赖尚未解释的“模型、参数、后验”等词。
2. **尝试朴素办法**：先观察或用常识判断，让读者有参与的起点。
3. **出现具体困难**：用数据/图说明哪里不够；不只说“这个方法不好”。
4. **引入工具**：为解决刚才的困难解释概念，再命名；符号、单位、假设首次出现即交代。
5. **跟做一次**：逐步说明为什么这么算，再提炼定义/公式/算法，必要时补短基础。
6. **回到原课**：具体对应老师的例子、术语、公式、代码或目标；有文件/cell/页码证据，不只在文末挂一个泛泛出处。
7. **变化与回忆**：改变条件独立尝试，随后进入少量现有卡。只需记要点的知识用主动回忆检查，不能伪称已验证迁移/实现能力。

这是作者检查顺序，不要求把七步显示成七个固定栏目。每个例子选择以内容为准：教师原例清楚时优先沿用；抽象时用生活小例子搭桥，再回原题。幽默只服务难点，不能让故事盖过学习任务。阅读时长是设计估计，做题/补课另计。

## 四、题目与实验采用任务式讲解

原题和必要数据/图/接口 → 练习的知识 → 解题/实现思路 → 关键步骤 → 结果检查 → 易错点。

题干、答案与提示双语对齐，题图在答案展开前可见。依据原题改写与教师原话、官方解答与我们的推导分别标明。已有卡内容通过 ID 引用，避免维护第二套题答。代码、抓包和实验结果仍需实际执行，不能编造结果或让背答案替代实践。

## 五、本轮验收与后续维护

- 开头能否让从未学过该主题的人说清“现在要解决什么”？
- 每个新术语是否由前面的需要引出，并在使用前解释？
- 原课例子/推理/活动是否能在网页找到，而不是只剩我们的新故事？
- Lecture/Chapter 与配套活动对应是否有材料依据，跨章与未知是否明确？
- 图文、双语题答、首轮卡、原深链和手机显示是否实际可用？
- 没有因为目录重组增加重复卡；保留 50 节既有 ID，先改必要讲述，不批量套用新模板。
